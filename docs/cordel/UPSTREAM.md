## Remote policy

`origin` points to `https://github.com/mylife-as-miles/cordel-engine.git` and is
the authorized CORDEL publication destination. `upstream` points to
`https://github.com/renpy/renpy.git` for reference and future integration work.
**Do not push CORDEL commits to upstream.** The original bootstrap used only
`upstream`; the current remotes were configured during the owner-requested fresh
history publication. Do not treat the upstream foundation hash as local ancestry.

Verify locally:

```sh
git remote -v
git branch --show-current
git log --oneline --max-count=5
git rev-parse --is-shallow-repository
```

## License and attribution policy

Preserve all source-file copyright and license headers. The canonical license
document in this checkout is [sphinx/source/license.rst](../../sphinx/source/license.rst);
`after_checkout.sh` creates an ignored `LICENSE.txt` link to it.
The project metadata in upstream `pyproject.toml` says MIT, but the license document
also identifies LGPL-derived portions and third-party terms. Do not describe a
complete binary distribution as MIT-only.

For each future distribution:

1. Record the exact source and binary dependency versions and build options.
2. Include MIT notices and applicable third-party license texts and credits,
   including sample artwork credits if those assets are distributed.
3. Identify LGPL components and versions. Provide applicable source and
   modifications and the required means of replacing/relinking libraries;
   bundled/static linking needs particular attention. A source URL alone does
   not settle every distribution obligation.
4. Check optional components separately: Live2D Cubism is enabled only when
   `CUBISM` is set, and its SDK terms are not covered by Ren'Py's MIT license.
5. Do not assume the CC0 exception for projects generated by an unmodified
   released Ren'Py automatically applies to a modified CORDEL engine.

Use the existing MIT license for original CORDEL documentation additions, without
relicensing upstream files or asserting a new copyright owner. Future code must
include appropriate actual contributor notices. Upstream's contribution policy
in `README.rst` requires human understanding/review of submitted changes; Phase 0
has not been submitted upstream. Publication to the CORDEL repository does not
change upstream attribution or contribution requirements.

## Synchronization strategy

Keep upstream files stable while experiments live in CORDEL directories. Treat
Ren'Py globals, compiled-module ABI, serialization classes, shader dialects, and
SDL changes as integration-sensitive boundaries.

CORDEL and Ren'Py now have unrelated Git roots. Do not perform an ordinary upstream
merge or use `--allow-unrelated-histories` without a deliberate integration plan.
For an update, inspect Ren'Py's diff from the recorded foundation in a separate
upstream checkout, then apply/review the selected changes on a CORDEL integration
branch. Record both source revisions and the imported change set. Use a matching
SDK or compile its native modules; rerun baseline tests and compare known failures.
Preserve CORDEL's published history and never copy SDK source over the checkout.

Do not mix native artifacts from different revisions or architectures silently.
When CORDEL diverges intentionally, record the reason, affected subsystem, adapter
contract, and expected upstream maintenance cost in an architecture decision.
